#### 1.27.1 - 2026-09-24

- **Action required for self-signed setups:** the credential toggle **Allow Self-Signed Certificates** (`allowSelfSignedCertificates`) is renamed to **Ignore SSL Issues (Insecure)** (`ignoreSslIssues`), as requested by the community package review. The scanner treats any field name containing "cert" as a secret and demands `typeOptions: { password: true }`, which is not an option for a boolean: n8n up to at least 1.123 then fails to load the whole credentials page ("startsWith is not a function"). n8n drops the old field on load, so installations that had the toggle switched on must open the TaxMetall API credentials once after the update and switch **Ignore SSL Issues (Insecure)** on again. Until then requests fail with a certificate error; the node now adds a hint pointing to this toggle to such errors. Behavior and default are unchanged.
- Renamed the resource label **DMS** to **Document Management** to avoid the scanner's plural-name match. The stored resource value remains `dms`, preserving existing workflows. The canvas subtitle and the action label ("Create a file in document management") follow the new name, and "DMS"/"TaxDMS" were added as search aliases so the node stays findable under the old name.
- Added explicit light and dark icon variants for the node and credentials (`TaxMetallLogo_light.svg` in the original dark blue for the light editor theme, `TaxMetallLogo_dark.svg` in a lighter blue for the dark theme). Both are now pure vector graphics, replacing the previous logo with an embedded PNG (about 5 kB instead of 70 kB each).
- Removed the lint suppression comments for both resolved review findings.

#### 1.27.0 - 2026-09-23

- **Statistic → Execute** gains four always-visible checkbox fields: **Only Open** (`ChkNO`), **Without Blanket Orders** (`ChkOR`), **Not Printed** (`ChkND`) and **Not Emailed** (`ChkNM`). TaxMetall's own report UI offers these as checkboxes for many reports (e.g. "Nur Offene", "Ohne Rahmenauftraege"), but the SQL parameters behind them were previously only reachable by typing the exact name into a generic collection field the node did not expose. All four are now sent on every execution (`'1'` or `'0'`, never omitted), so an unchecked box reliably means "off" instead of being silently absent. Reports that do not use a given parameter simply ignore the extra value. **Additive / non-breaking.**
- **README**: documented the four new fields, and corrected the note on which report types are supported — the service now exposes a small, fixed set of built-in "n.g." (not-printed/not-emailed) reports in addition to Individual and Business Cockpit reports; most other static system reports remain unavailable.
- Requires TaxMetall API Service with `ChkNO`/`ChkOR`/`ChkND`/`ChkNM` support in `/api/statistics/execute` (already generic in the service; no version bump needed there).

#### 1.26.0 - 2026-08-06

- **Purchase Invoice** resource gains a **Create** operation with two input modes.
  - **Parameters** mode takes header and positions as fields. Positions may reference an article or be pure free-text lines (a Description alone is enough). Optional per position: price-per-quantity, discount, VAT rate or VAT key, G/L account, cost center, purchase order reference, service date, or a fixed line total that overrides the calculation.
  - **E-Invoice** mode takes an EN 16931 file (XRechnung/UBL or ZUGFeRD/Factur-X/CII) as Base64 or plain XML and lets the service read it. The syntax is detected by XML **namespace**, not by namespace prefix, so prefixed and prefix-less documents both work. If no Supplier Number is given, the supplier is identified from the file — VAT ID, then IBAN, then exact name — and ambiguity is reported instead of guessed.
  - **Discount Handling** (e-invoice mode) decides where document-level allowances and charges go: each as its own invoice line keeping its own VAT rate (default), or onto the header fields for absolute discount and freight. The header variant is rejected when the invoice mixes VAT rates, since the absolute discount carries no rate of its own.
  - **Validate Only** runs every check and the full calculation without creating anything — useful to verify a supplier, the totals and whether the invoice already exists before committing it. It uses the same calculation path as the actual creation.
  - The service records the invoice only: no approval chain, no stock valuation, no posting. Those remain manual steps in the ERP.
  - Requires TaxMetall API Service with `POST /api/create-purchase-invoice`.
  - Full German UI translation included. **Additive / non-breaking.** (Correction: the translation file never took effect in n8n and was removed in 1.26.1. The node UI is English.)
- New resource **Workflow** with **Execute** and **Get Many** operations.
  - **Get Many** lists the workflows the ERP exposes. **Execute** starts one and passes its declared variables as name/value pairs. Both dropdowns are filled from the service, and the variable list reloads whenever another workflow is selected, so only variables the chosen workflow actually declares can be picked.
  - **Strict Variable Check** (on by default) makes unknown variable names fail the call. Turn it off to ignore them silently, which is how the ERP itself behaves.
  - Requires TaxMetall API Service with `GET /api/get-workflows` and `POST /api/execute-workflow`. Both endpoints are **disabled by default** in the service and must be switched on with `[Workflow] Enabled=1` in `config.ini`.
  - **Additive / non-breaking.**
- **README** now states the minimum TaxMetall API Service version per resource and operation. The endpoints this node calls were added to the service over time, so an operation only works if the on-premises service is new enough; calling one it does not know returns HTTP 404. A table under [Compatibility](README.md#compatibility) maps every resource and operation to the service version that introduced it, and each affected resource section repeats its requirement. This is documentation only: the node performs no version check and no version handshake, so nothing about its runtime behavior changes.
- From TaxMetall API Service **1.26.0** on, `GET /api/validate` also returns the running service version, which means the credential **Test** button shows it. Older services simply omit the field. **Documentation, non-breaking.**

#### 1.23.1 - 2026-07-06

- Document Sync / **Check & Download New Documents**: the initial claim request (`check-new-documents`) is now wrapped in its own error handling, matching the resilience the per-document download loop already had. Previously, if that single request failed (e.g. a transient server-side DB connection hiccup), it aborted the entire node run with a generic `Service unavailable` error — regardless of the "Continue On Fail" setting. Now a failed claim is surfaced as one output item (`success: false`, `claimError`, `httpCode`) and the run continues normally. **Fix, non-breaking.**

#### 1.23.0 - 2026-07-02

- Document Sync / **Check & Download New Documents**: server-side skips are now surfaced as their own output items instead of being swallowed. Previously, when the service skipped a claimed entry (e.g. `file_not_found` — the referenced file no longer exists at its path), the operation emitted the same `{ success: false, count: 0, description: 'No new documents found' }` as an empty queue, which was misleading. Now each entry in the response's `skipped[]` is emitted as an item with `success: false`, `skipped: true`, a `skipReason`, and the `dateiname` (the resolved path where the service expected the file), so downstream can react to missing documents distinctly from an empty queue. The service also now reports the **resolved full path** in the `file_not_found` skip entry (previously the bare stored name). `No new documents found` is still emitted only when the queue is genuinely empty (nothing claimed and nothing skipped). **Additive / non-breaking** for the empty-queue and normal-download paths.

#### 1.22.0 - 2026-06-26

- Document Sync / **Download Document File** + **Check & Download New Documents**: new **Unpack MSG/EML** option. When enabled, `.msg` and `.eml` documents are delivered automatically unpacked as JSON (`meta`/`body`/`attachments`, attachments Base64) in the same step, instead of the raw file — no separate Unpack MSG call needed. The service detects the format intelligently: other file types are returned unchanged as a binary file (no error, marked with an `X-Unpack: forwarded` header), and a `.msg`/`.eml` that fails to parse falls back to the raw file too. When unpacked, the output item carries JSON (no binary). Backed by a new `unpack` flag on the service endpoint `GET /api/document-file` (now also parses `.eml` via Indy, alongside the native `.msg` reader). **Additive / non-breaking** — the option is off by default, so existing downloads are unchanged.

#### 1.21.0 - 2026-06-26

- Document Sync: new **Unpack MSG File** operation. Reads a stored Outlook `.msg` (resolved against the ERP mail folder SDTMP, or a full path) and returns its full content as JSON in one call: `meta` (subject, sender, sent date, recipients with to/cc/bcc), `body` (text + html), and `attachments[]` (file name, MIME type, size, content ID, inline/hidden/embedded flags, and Base64 content). Pull whatever you need downstream in n8n. Toggle **Include Attachment Content** off for a faster metadata-only listing (`sizeBytes` still included). Parsed natively via OLE structured storage — **no Outlook/MAPI installation required**. Backed by the new service endpoint `POST /api/unpack-msg`. **Additive / non-breaking.**

#### 1.20.2 - 2026-06-24

- Docs only (no functional/runtime change): corrected the Document Sync section of the README against the current service code. Removed obsolete statements that no longer match the implementation:

#### 1.20.0 - 2026-06-23

- Document Sync: removed the two parameters that were already marked **legacy** — **Lease Token (Legacy)** (Download Document File / Report Transfer Status) and **SharePoint URL (Legacy)** (Report Transfer Status). #### 1.19.0 - 2026-06-23

- Document Sync / Report SharePoint Transfer Status: new **Payload Fields** (key/value) area to build a custom flat JSON payload for the entry (e.g. `sharePointUrl`). Keys must be non-empty and unique (duplicates/empties raise an error), values are strings, total payload limited to 8 KB. The legacy single **SharePoint URL** field still works as a fallback when no Payload Fields are set. **Additive / non-breaking.**
- Document Sync / Check New Documents: DELETE events now return the **full stored `payload`** of the correlated prior upload (or `null` after retention), alongside the existing derived `sharePointUrl`. CREATE events for mail documents (`Typ=2`) now include an **`email`** object (`from`, `to`, `subject`, `date`).
- Document Sync / Create Document: the **SharePoint URL** is now **optional** — create a document without a SharePoint reference (e.g. when the storage export is handled later by WF1 via "Also Export to Storage").
- Service: `/api/sharepoint-transfer-status` accepts a generic `payload` object (stored flat) in addition to the legacy `sharePointUrl`; `/api/create-new-dokument` no longer requires `sharePointUrl`. No DB schema change.

#### 1.18.0 - 2026-06-23

- Document Sync / Download Document File & Report SharePoint Transfer Status: the **Lease Token** parameter is now **optional and marked legacy** (renamed display to "Lease Token (Legacy)"). The service no longer validates `leaseToken`/`token` — claim locking moved to an in-memory, per-tenant lock — so the field can be left empty. **Non-breaking:** the node still sends the value if provided, and the service still returns a dummy `leaseToken` in the Check New Documents response for backward compatibility. Full removal of `leaseToken`/`token` from request, response and `downloadUrl` is planned for a future **major** version (Phase 2).

#### 1.17.0 - 2026-06-22

- Document Sync / Create Document: new **Also Export to Storage (Disable Loop Guard)** option (off by default). When off, an imported document is created in TaxMetall but is not re-exported (the ERP sync trigger skips its own echo). When on, the created document is additionally queued for export (WF1) — useful to mirror imported mails/documents to your external storage (e.g. SharePoint) as well. Sent as `suppressLoopGuard` to `/api/create-new-dokument`; the service writes a distinct source marker so the trigger does not suppress the event. No infinite loop: the export path does not create another TaxMetall document.

#### 1.16.0 - 2026-06-22

- Document Sync / Report SharePoint Transfer Status: the failure text is now sent to the service under `errorMessage` (previously `error`, which the service ignored — the custom message was silently dropped and only a generic default was logged). The service accepts the old `error` key as a fallback, so older node versions keep working. The recorded log entry now contains the message you provide.
- Document Sync / Download Document File: file names are now parsed identically to "Check & Download New Documents", including RFC 5987 percent-decoding of the `Content-Disposition` `filename*` value — so downloads with non-ASCII names (umlauts, etc.) get the correct file name instead of a percent-encoded one. The shared parser also decodes defensively (a malformed value falls back to the raw name instead of throwing).

#### 1.14.3 - 2026-06-18

- Document Sync / Report SharePoint Transfer Status: the "Success" parameter is now a text field instead of a checkbox, so the value can be passed through from a previous step via an expression (e.g. the upstream node's success indicator) rather than being toggled manually. Accepted truthy values are `true`, `1`, `yes`, `success` (case-insensitive); anything else is treated as a failed transfer. The node coerces the value to a real boolean before calling the service, so the API request is unchanged. Because the value can now be an expression, the "SharePoint URL" and "Error Message" fields are always shown for this operation (n8n cannot evaluate an expression to drive conditional visibility) — fill whichever applies. Removed stale "retry / dead after maximum" wording from the field descriptions (failed transfers are retried unconditionally on the next poll).

#### 1.14.2 - 2026-06-18

- Document Sync: updated the node to the service's new event contract. #### 1.14.0 - 2026-06-16

- Document Sync / Check & Download New Documents: the operation now always returns something. When no documents are found it emits a single summary item `{ success: false, count: 0, description: "No new documents found" }` instead of empty output, so you can drive a "nothing to do" branch. When documents are found, every item additionally carries `success: true`, `count` (total documents in the batch) and `index` (0-based position) alongside the existing metadata/binary — useful for loops and for telling the empty result apart via `{{ $json.success }}`.

#### 1.13.0 - 2026-06-16

- Document Sync: added "Check & Download New Documents" operation — combines "Check New Documents" and "Download Document File" into one step. It claims a batch from the sync queue and, using the batch-wide lease token, downloads the file for each `document.created` entry, returning one item per document with the metadata in `json` and the file in `binary`. Non-file events (e.g. `document.deleted`) pass through as metadata only; a single failed download (file vanished/skipped server-side between claim and download) is recorded on that item (`downloadError`/`httpCode`) without aborting the rest of the batch. The lease token is included in the output so a downstream "Report Transfer Status" can still acknowledge each entry. The low-level "Check New Documents" and "Download Document File" operations remain available.
